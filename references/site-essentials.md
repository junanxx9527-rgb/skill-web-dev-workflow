# 站点级通用能力(Site Essentials)

时机:搭项目骨架阶段(或用户说"把网站补完整"时),**主动**把这份清单整理给用户勾选——
而不是等用户日后一项项想起来再提。能用 AskUserQuestion 这类多选工具就用,否则列成清单一次性问。

问法示例:"骨架搭好了。下面这些站点级能力,要哪些我一起做了:…"

## 勾选清单

| 项 | 说明 / 默认建议 |
|---|---|
| 深色模式 | 跟随系统 + 手动切换;CSS 变量/主题方案要在搭骨架时定,后补要全站改色值 |
| 404 / 500 页 | 强烈建议默认做:风格与站点一致,带回首页链接 |
| SEO 基础 | 每页 title/description、OG 标签(分享卡片)、sitemap.xml、robots.txt;内容站必选 |
| favicon / 站点图标 | **项目基本完工时才做**(不在骨架阶段),按用户思路/难度分流——展开见下方"favicon 时机与做法" |
| 设置页 | 有用户系统时建议有:资料、密码、偏好(深色模式开关放这) |
| 法律页 | 隐私政策 / 服务条款占位页;面向公众或有用户数据的站点建议有 |
| 分析统计 | 如 Plausible/Umami/GA,按用户隐私偏好选 |
| RSS | 博客/内容站才相关 |

(多语言 i18n 不在此清单——它是架构级决定,已前移到启动对齐阶段问,见 `intake.md`。)

## 视觉身份:一次定,各处复用

favicon 做不好,根因往往不是 favicon 本身,而是**没有一个统一的站点视觉身份**——主色、辅色、字体、那个"最小标记"(logo/字母组合)。
这些一旦在搭骨架阶段定下来(用 CSS 变量/主题 token 承载),favicon、深色模式、404 页、OG 分享图、加载动画就都从同一套身份派生,自然一致;
否则每个视觉资产各做各的,全站透着拼凑感和 AI 默认味。

- 搭骨架时确立视觉身份,记进约定文档(主色值、字体、标记形态)。
- **真正的视觉执行交给设计类 skill**(`frontend-design` / `frontend-design-anchors`)——本 skill 只负责"确保这件事被定下来并被复用",不重复造设计指南。
- 所有视觉资产都引用这套身份,不要临时另起炉灶。
- **favicon 本身不在搭骨架阶段做**——见下方"favicon 时机与做法",它放到项目基本完工时再做。

## favicon 时机与做法

**时机(工作流触发点):项目基本完工时再做 favicon,不在搭骨架阶段做。**
原因:这时全站视觉、主色、最终调性都定稿了,做出来的图标才贴合成品,不会给半成品配图标然后返工。
(视觉身份的主色/标记在搭骨架时已确立,见上;favicon 在此基础上落地。)
到了收尾阶段**主动发起**,不等用户提。按下面三条分支走:

### 分支一:用户有思路,且样式简约不难 → Claude 直接做并接入

用户已经说清想要什么(比如"就用首字母 + 主色""一个圆角方块里放个箭头"),而且属于简约可代码实现的类型
(单个字母、简单几何形、纯色/双色)——**直接创作(SVG 优先)并接入,不用再问**,然后配齐资产(见下)。

### 分支二:用户不知道怎么弄 → 先探讨,再按难度分

先和用户**简短探讨**:站点调性、想要的感觉、有没有偏好的颜色或符号。探讨完评估难度:

- **简单**(能用字母标记或几何图形表达)→ Claude 来,直接做并接入。
- **太难**(需要插画、复杂图形、具象 logo,超出代码画图标的能力)→ **给一段填好本站视觉身份的提示词**,
  让用户拿去 GPT / 图像生成工具做,**并明确告诉用户把生成的图片放进哪个目录**(如 `public/` 或 `public/icons/`)、要哪些尺寸;
  用户放进来后,Claude 负责转格式、配齐资产、接入页面。别让"拿到图"和"用上图"之间断档。

  提示词必须现场定制(带真实主色值、站点名/标记、调性),不要给通用空模板。模板:

  > 设计一个网站 favicon(站点图标)。品牌:**<站点名>**,行业/调性:**<一句话定位,如"极简的开发者工具">**。
  > 主色:**<主色 HEX>**,辅色:**<辅色/留白>**。核心元素:**<一个字母或一个简单图形,呼应 logo>**。
  > 要求:扁平、几何、极简,单一主体,高对比;**必须在 16×16 像素下依然清晰可辨**;不要文字段落、不要细小笔画、不要照片质感、不要渐变堆叠;
  > 居中、四周留安全边距;输出正方形、背景<透明/纯色>。请给出 SVG 或高分辨率 PNG。

### 无论哪条分支,做出来都守两条质量底线

1. **16px 可读优先**:浏览器标签页就 16px。只放**一个**形状或**一个**字母,高对比,不塞细节、不放多字文本、不放完整 logo 的缩小版。
   做完在心里(或实际)缩到 16px 看一眼:糊了就简化。
2. **资产配齐,不只丢一个 PNG**:
   - SVG favicon(矢量、随分辨率清晰、可适配深色)优先;
   - ICO/PNG 兜底(32、16);
   - `apple-touch-icon` 180×180(iOS 加到主屏);
   - manifest 的 192 / 512(PWA / Android);
   - `<meta name="theme-color">` 用主色(移动端地址栏配色)。

**诚实原则**:简约可代码实现的自己做;太难的不硬撑出平庸结果——老实说"这个超出我画图标的能力,用上面的提示词去图像工具做更好",
把选择权交给用户,比闷头交付一个难看的图标好。

## 纪律

- 用户勾选后,把"要的"和"明确不要的"都记进约定文档,日后不再重复问。
- 没勾的不做,但其中影响后期改造成本的(如深色模式),提醒一句成本差异再让用户定。
- 这份清单也是举一反三的:特定类型站点有自己的"常识项"(电商→购物车/订单邮件;文档站→搜索),
  按项目类型自行补充进勾选列表。
